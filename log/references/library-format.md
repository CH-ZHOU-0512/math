# 学习库格式

log、write 和 manage 使用同一约定。新条目采用 v2；已有 v1 继续可读，不因升级技能自动迁移。每份内容以 Markdown 原文为准，YAML 属性支持结构化检索，正文保留完整的理解与证明。索引若以后建立，只是可重建的派生数据。

## 位置与目录

先确认 Obsidian Vault 根目录与资料子目录的关系；以下为资料放在 Vault 子目录中的示例，实际目录以项目约定为准，不自动搬迁：

```text
Vault根目录/
  学习库/
    自动笔记/
    自写笔记/
    讲义库/              每份讲义一个中文主题目录，含条目和指定的原文件
    题库/                每道题一个 Markdown 文件
    附件/
  .history/                   有修改时才创建，排除出日常检索
```

目录位置由用户给定或已有配置确定。不在技能目录内存放学习资料、绝对路径配置或索引。wikilink、files.path 与新附件路径均相对实际 Vault 根目录；资料位于子目录时保留该前缀，不把子目录另建成 Vault。

## 通用属性

每条记录以 `---` 包围一段 YAML。字符串含冒号、井号或公式时正确引用；日期写为带引号的 ISO 日期，避免解析成不同类型。列表使用真正的 YAML 列表，不用逗号字符串代替。

| 字段 | 类型与取值 | 含义 |
| --- | --- | --- |
| schema | 字符串，`math-learning/v2` | 本格式版本 |
| id | 字符串 | `N-`、`L-`、`Q-` 加 12 位随机小写十六进制字符，分别对应笔记、讲义、题目 |
| type | `note` / `lecture` / `problem` | 记录类型 |
| title | 非空字符串 | 清楚的中文主题标题，不含机器编号 |
| created | `YYYY-MM-DD` 字符串 | 条目创建日，不冒充实际学习日 |
| updated | `YYYY-MM-DD` 字符串 | 最近修改日 |
| topics | 字符串列表 | 规范的知识点名，如“罗尔定理”“辅助函数” |
| learning_status | `not_started` / `in_progress` / `studied` / `review_due` | 未开始、进行中、已经学过、需要复习；都不等于永久掌握 |
| verification | `unchecked` / `partial` / `checked` | 现行数学内容未核对、部分核对、已逐项核对 |
| sources | 对象列表 | 每项含 kind、ref、locator，见下 |
| related | ID 字符串列表 | 关联的现有条目；无关联用 `[]` |

生成 ID 可用 UUID 的随机部分截取 12 位，再在目标库的相应条目范围检查是否已用；发生冲突重新生成。ID 创建后不因改名或搬动改变。标题、文件名与目录名使用清楚的中文主题，不加编号、题号、日期前缀或 ID；ID 仅存属性。来源题号与单元进度存正文或来源字段；数学内容自身的数字照常保留。同名用主题差异词区分，不追加流水号。分类目录已有的 `20_`、`30_` 等排序前缀保留。已存在的文件不因读取而批量改名。

`sources` 每项包含：

- `kind`：`chat`、`book`、`pdf`、`web`、`self` 或 `other`。
- `ref`：可靠的文献标识、实际 URL、库内相对文件路径，或可识别的对话/自编来源说明。没有真实会话链接时写“本次对话：主题”，不能制造链接。
- `locator`：章节、题号、消息位置或页码说明；不知道就用 `null`。例如“PDF 第 8 页；印刷页 5；例 2”。

实际来源未知时 `sources: []`，必要时在简短学习记录说明出处未记录。不填写猜测的页码、题号和版本。保留用户提供的外部来源标识；新复制到库中的附件使用相对路径。

`verification: checked` 表示本次对现行断言和论证完成了数学核对，不宣称机器形式化证明；有必要限定范围时在简短学习记录说明。历史错误尝试以明确的历史标签保留，不与现行正确结论混淆。核对只覆盖局部时用 partial。

## 各类型的额外属性

### 笔记 note

新条目必须有 note_origin: automatic 或 self_written，分别进入“自动笔记”与“自写笔记”。历史条目没有字段时不猜，标明待确认；不得自动提升为 self_written。两类可以关联，但不是可直接合并的重复记录。

self_written 另有 author_status: draft 或 confirmed，分别表示待作者确认与作者已确认。作者确认不代表所有数学断言已核对，verification 独立记录；未吸收的 AI 核验与建议留在对话或按当前请求、已有持续授权存入关联自动笔记，不进入自写笔记正文。automatic 不填写 author_status。

自动笔记正文可保留定义、条件、证明与学习过程。自写笔记以用户理解、感悟及其理由为主体，定义等背景只留解释个人观点的最小片段，不能扩写成知识点汇编。两类都保留实际卡点、修订与待复习问题。不同概念不为凑篇幅塞进一个超长条目；紧密相关的小结也不必过度拆分。

### 讲义 lecture

- `files`：对象列表，每项含 `path` 和 `role`。path 是相对 Vault 根目录的实际文件路径（例如 `学习库/讲义库/函数性质讲义/函数性质讲义.pdf`），role 为 `pdf`、`source` 或 `attachment`。只有确实存在的文件才写入；暂时只有聊天文本时用 `[]` 并保留正文。
- `studied_parts`：字符串列表，明确实际学过的章节、页码或知识点。只做了第 1 节就只写第 1 节；还有计划中的部分未学时 learning_status 为 in_progress。

正文给讲义范围、目录、已学和待学部分、相关题目及复习提示。原文件保留版本；新版本不要悄悄覆盖与历史页码关联的旧版。

### 题目 problem

- `difficulty`：`A`、`B`、`C` 或 `unrated`。A 是定义与直接应用，B 是方法选择和连接，C 是拓展。按当前学习背景标注；没有可靠分层依据用 unrated。
- `methods`：字符串列表，记录实际用到的方法，不塞入所有可能相关的标签。
- `completion`：`independent`、`guided`、`explained`、`unresolved` 或 `unknown`。

completion 的区别：关键方法与证明由用户完成可记 independent，常规化简或表述修正不自动降级；有关键提示后完成记 guided；主要阅读或听完整解答记 explained；明确仍未解决记 unresolved；不知道完成方式记 unknown。仅有“我能独立做”的能力自述时，保留自述且不覆盖既有 completion；明确说明某次无提示完整完成时可按用户报告记录 independent，并注明证据来源。依据不足不能把“是否独立完成未知”说成“尚未解出”。以后独立重做成功可以更新，同时保留旧经历。

题干、用户尝试、提示介入、最终解答、卡点与修正分别写在正文中。一题多个子问先保留在同一条目，并标清各问进度；任一必做子问未解决时整体 completion 为 unresolved。需要按子问检索时可在正文保留稳定小标题。

## 学习记录与交叉引用

正文保留概念、条件、证明、方法来源、真实尝试、卡点、错因与修正。来源、完成方式、作者确认与核对状态优先使用属性，属性未涵盖的日期、关键提示或核对范围集中写一段必要的简短学习记录；无实际内容的栏目删除，不逐段重复身份审计、能力免责或“并非独立发现”等元说明，不写课堂调度指令。可以引用简短原话，不能伪造用户说过的话、作者认领或独立发现。通常归档已学内容；用户明确要保存还没开始学的材料时用 not_started，不因文件已存在就记为 in_progress。

`related` 用稳定 ID。正文中的 Obsidian 链接使用真实库内路径，例如 `[[学习库/自动笔记/主题标题|主题标题]]`（示意，按实际文件替换），写入前确认目标存在。ID 本身不是 Obsidian 自动识别的目标，不能只填一个没有对应文件的 ID 作为 wikilink。图片和附件同样检查实际相对路径。

链接清单、题目列表和可选索引从原文派生，不成为另一个需要分别维护的正确答案库。

## 兼容、合并与字段检查

已有记录使用其他格式时，读取其字段语义，不强加本格式。迁移需要明确任务和范围；保留未知字段和用户扩展字段，不因为本表未列出就删掉。

用户要求合并同一条目时，先核对笔记来源，自动笔记与自写笔记不得直接合并。确认同类同一条目后，旧条目可以保留通用属性并增加 `redirect_to: 目标ID`，正文仅保留迁移说明和目标链接。转向条目不要求 type 的额外字段，不作为独立新结果重复计数。读取时循转向核对目标存在，遇到循环或缺失停止并报告。

写入后至少核对：必填字段和类型、ID 与 type 对应、日期格式、枚举值、来源格式、附件存在、related 和实际链接可达。不要运行资料自带脚本来“自动修复”格式。格式检查通过不等于数学证明正确或用户已经掌握。
