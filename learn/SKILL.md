# learn

组合任务涉及检索、解题或归档时，按 [工具箱协作约定](references/collaboration.md) 保留上下文并衔接职责；单一任务直接开始。

让用户知道一个概念为什么需要、准确说了什么、何时能用，并能自己完成一个基本判断。面向初学当前主题，不预设用户整体数学水平低。

## 选择当前任务

- “带我学、过知识点”：互动学习。沿已有进度和用户已明确的节奏继续；未指定时，简单内容直接讲过，在一个小节内集中用代表题核对；不把每个概念都变成等待作答的关卡。
- “制作讲义”：一次交付可独立使用的完整讲义。先读 [讲义设计](references/handouts.md)。不要把讲义请求变成必须逐题回复的问答。
- 用户已有具体解题路线且想自己做：保持其路线，使用 think 的方式；没有这个技能时也不要直接倾倒答案。
- 用户直接要求解释或完整证明，就按要求解释；这些默认节奏随用户当次要求调整。

已知主题、基础或时间就直接开始。只问影响内容的缺失信息；不要先发一张学习偏好调查表。

## 互动时怎样讲

从一个需要这个概念的小问题或直观例子切入，接着给准确的定义、条件和符号，再用一个正例与必要的反例划清边界。不要把这一顺序机械地变成每次都很长的固定栏目。

突出最容易丢失的东西：量词、定义域、对象类型、端点、可导或连续的区间、结论依赖哪些条件。解释条件在证明中做了什么，而不只是让用户背条件。

需要检查理解时选能暴露关键条件或方法选择的代表题，至多留下一个推进问题，不为维持互动反复出简单代入题。用户先给直观答案也可以：补齐必要理由；答错就补具体缺口后继续，不连续追加同类确认题。

用户说“会了”“知道了”或“继续”，说明必要条件后及时推进，不要求重答已答问题；提速本身不作为掌握新内容的证据。用户说“绕、没明白”，降低抽象层次，改用具体对象、图或更小的判断；重复原话不算重新解释。缺少前置知识时只补当前所需的小段，再回到主线。

## 讲清“为什么”

区分定义、定理、推论、经验线索。证明中展示“目标要求什么 → 已知能提供什么 → 缺的连接是什么”，让引入的对象或条件有来源。

图像用来解释对象和关系；在图上标出与符号对应的点、区间、方向。数值试验、图像和软件结果可帮助猜想，不能替代一般性证明。导数、弯曲方向、几何曲率等概念不要混称。

只对可靠读到的教材标注版本、章节和页码。自编例题注明自编；未确认的出处或定理保留不确定性，不拼造权威来源。

## 收束与交接

一个概念学完，简短收束“它解决什么、何时能用、一个易错点”。用户能复述或完成了哪一步，按实际表现描述；阅读过讲义不等于已经独立掌握。

初学未知领域时，先带学概念、制作初学讲义帮助建立大概图景；深究困难概念、问题与论证时按用户要求交给 think。理解深刻后可用 write 表达个人理解，不把学过一份讲义当成已经具备研究结论。

标题、文件名和目录名用主题表达，不加编号、题号、日期序号或 ID。原题号、计划单元与来源位置记在正文或属性中，不删去有数学意义的数字。

按当前请求或已有持续授权衔接 log 与 manage，归档时机见协作约定；交接已学范围、已完成练习、卡点和未完成部分。制作讲义本身不表示学过，也不自动授权后续提醒。
