# 检索与修改的具体做法

## 从请求到原文

优先使用明确 ID、文件路径、题目来源或讲义页码。模糊检索先看目录和元数据，再阅读候选正文；同义词扩展要围绕同一概念。文件名相近但出处或条件不同，保留为不同候选。

Markdown 可用 rg 检索指定目录，排除 `.obsidian`、`.history` 和缓存。包含空格、中文或通配符的路径作为字面路径传给文件工具；给 rg 的搜索文字按数据参数处理，不拼成待执行的 shell 代码。

PDF 命中后回到实际页面核对公式、条件、上下文。记录一基 PDF 页码与实际印刷页码；没有印刷页号就写未标，不拿 PDF 页号代替。表格、扫描件或乱码需要看页面，不因抽取文字缺失就判断内容不存在。

已有索引可以用于召回，但记录不存在、修改时间冲突或命中内容与文件不符时，以当前源文件为准。新建全库索引、全库 OCR 或全量哈希是另一个明确范围的任务，不作为普通查询的前置条件。

## 局部编辑

1. 读取当前文件，确定被要求修改的段落和受影响的元数据。若“改一下这份讲义”无法确定目的，先问具体修改方向，不能自行重写全篇。
2. 准备最小补丁，保留稳定 ID 和用户手写内容。把修改前文件复制到库内 `.history/日期-修改主题/原相对路径`（同日同主题冲突时补充时间），或使用当前库已有的可恢复版本机制。备份不作为现行学习条目参与检索。
3. 写入前确认文件仍与所读版本一致，可用目标文件的内容哈希或精确补丁上下文核对。发生并行编辑就重读并协调，不直接覆盖。此处只检查本次目标，不扫描全库做哈希。
4. 应用修改，更新 updated。数学实质变化后重查受影响论证；未完成核对就设置 partial 或 unchecked。单纯排版改动不改变既有核对结论。
5. 重读，检查差异、字段、公式和链接。保留一条简短修改记录，说明改了什么及原因。给用户真实结果和可恢复位置。

补丁失败或附件复制失败时，列出已完成和未完成项。需要回退时先确认不会覆盖失败后产生的新编辑；保留备份和恢复清单。没有事务工具时，不把多文件改动宣称为原子操作。

## 状态与学习历史

- 用户说“我已经学完了”，可据其说明更新 learning_status；不要另设考试。
- 用户说“这题能独立做了”，先记为用户自述；仅有能力自述时不覆盖既有 completion。用户提供独立作答，或明确说明某次无提示完整完成时，按相应证据更新并注明来源，保留旧的提示经历。
- 只修正错别字、换了讲义文件或重新排版，都不是学习程度变化的证据。
- 修复证明时，把现行解答与历史错误尝试分开。纠错后并不抹去最有复习价值的卡点。

维护正文时保留实质概念、条件、方法、真实思路、错因与修正；必要来源、完成方式和核对范围集中在属性或简短记录，不补入反复的身份审计、能力免责或课堂调度指令。

维护自写笔记时，将作者正文与 AI 核验、修订建议分开；未经用户认领的新观点不改成第一人称。自写与自动笔记不是可直接合并的重复记录。

## 重命名、移动和合并

只在用户要求的范围内操作。先列出源、目标、当前链接和冲突；目标已存在且不是同一条目时先处理冲突，不覆盖。检查解析后的路径仍在用户指定范围内。

保留原 ID。改文件名或位置时修复相关 Obsidian 链接、files 路径和目录引用；只为查找受影响引用进行范围内检索，不顺便重写不相关内容。验证新文件可读和引用可达后报告结果。

合并前读两份原文，核对是否确为同一概念记录、同一讲义版本或同一道题。保留来源、学习记录和各自有价值的内容。旧 ID 默认保留为带 `redirect_to` 的简短转向条目，字段遵循格式约定；不在同一次普通合并中永久删除原记录。

原始讲义的新版本单独保留并说明替代关系，旧版学习页码仍指向旧版。不把换版后的第 5 页假定为用户当时学过的第 5 页。

## 删除与批量处理

明确的删除请求覆盖哪些文件就只处理哪些文件，先保留可恢复副本；无法确定对象时列出具体候选。永久清除、批量改写或重建索引必须有对应范围的用户授权。

对批量任务先枚举受影响文件和改动类型；范围明确且已获授权即可执行，不机械要求二次批准。范围外的变化留在具体建议中。
